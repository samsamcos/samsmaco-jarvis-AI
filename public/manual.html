JARVIS Agent — 21 Tools NEW
How It Works
Chat at /jarvis-chat or call POST /api/jarvis. JARVIS reads your message, picks 1-3 tools from the list below, executes them in sequence, and streams a final reply. Uses Groq (fast) → Gemini (fallback) → Pollinations (always free) for AI inference. Provider scores are tracked automatically; best-scoring provider is favoured next time.

Job Registry NEW
Hierarchy
CEO (1) → Manager (15 groups) → Staff (601 members, ~40/group) → Jobs (6,751 jobs, ~11/staff). Every job has a unique job_id, group tag, webhook URL or SSH command, and semantic description stored in ChromaDB.
3-Tier Search Speed
Tier 1 — Alias Cache
<5ms
Exact keyword → pre-saved job_id mapping. Zero AI inference.
Tier 2 — Group Semantic
~100ms
Vector search inside one group. Fast when group is known.
Tier 3 — Full Semantic
~600ms
Searches all 6,751 jobs with cosine similarity. Always finds a match.
find_job Example
POST /api/jarvis
{"message": "find me a job for turning on kitchen lights", "wing": "house"}

JARVIS calls find_job(query="kitchen lights", group="House") → returns job card with name, job_id, manager, score, tier, and ms elapsed.
execute_job Example
POST /api/jarvis
{"message": "run job kitchen_lights_on"}

JARVIS calls execute_job(job_id="kitchen_lights_on") → fires webhook/SSH/n8n, returns result with method and ms elapsed.
⚠ Current Registry Size
Registry holds 6,751 jobs and 601 staff. Target is 42,000 jobs (15 groups × 30 staff × 90 jobs each). Check live count at /api/jarvis/config-check → registry.jobs.

alias jarvis='python3 /root/ai-browser/jarvis-cli.py'

Memory System — MemPalace NEW
What Is MemPalace?
Every conversation, decision, and tool result can be stored in ChromaDB — a local vector database. Memories are recalled semantically, so "what did I say about the kitchen lights last week?" finds the right entry even without exact keywords. Data persists across server restarts. No cloud dependency.
Wings (Memory Namespaces)
Wing: sam
Sam's personal memories — preferences, decisions, reminders. Only recalled when wing=sam.
Wing: gf
Partner memories — her preferences, shared decisions, household notes.
Wing: house
House state — which lights were last on, who was home, device history.
Wing: jarvis
JARVIS own notes — tool decisions, provider scores, job pipeline state.
Importance Scoring (1 – 10)

Keep forever

mem_cleanup
Runs automatically to free disk space. Deletes entries where importance < 3.0 AND older than 30 days. NocoDB-synced entries (source starts with noco) are always preserved regardless of importance. Call manually: POST /api/jarvis → "run mem_cleanup".

Mode Rules
Single-Room Personas
Personas JARVIS (sam), SAM (partner), and AI can only be active in one room at a time. The Nexus monitor thread automatically moves the previous room back to HOUSE (or GUEST if guest mode is on) when another room claims the same persona.
Guest Mode
Toggle via POST /guest-mode/on or POST /guest-mode/off on port 5011.
OFF (default): Rooms revert to HOUSE tab (4) when a single-room persona leaves.
ON: Rooms revert to GUEST tab (5) instead.
Group Memory & Revert Timeout
The Jarvis screen remembers the last staff slot used per group. Returning within the revert timeout (default 30 min) auto-restores that slot. After the timeout, the group reverts to its configured default (usually slot 1). Configure at Jarvis Setup → MEMORY tab.
Webhook Staff Switch Flow
POST /jarvis/webhook/{group}/{staff} → Looks up name from NocoDB (60s cache) → Saves authoritative state with timestamp → Pushes TTS + wake word to active voice box → Jarvis screen polls /api/active-staff every 3s and auto-switches group + highlights slot.
Provider Score Feedback Loop
After every JARVIS reply, the caller can send a score (1–5 stars) via the reply payload. Scores are averaged in data/provider_scores.json. Next request automatically routes to the highest-scoring available provider. View scores at GET /api/jarvis/scores or run jarvis --scores.
