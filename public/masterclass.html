Overview

🗺️ How the AI Builds a Workflow 3 Phases
📥
Phase 1 — Intake
You send a task.
System scans: nodes, jobs, rules, preferred sites.
Gemini asks 2-3 clarifying questions.
You answer → Phase 2.
📐
Phase 2 — Blueprint
AI reads your task + answers.
Loads these Rules + Preferred Sites.
Builds a step-by-step workflow.
Saves to /staff-temp instantly.
▶
Phase 3 — Execute
👁️ Supervised mode.
Each step runs one at a time.
High-risk steps pause for Telegram approval.
Final result sent to Telegram.
🔁 The Full Loop — Any Message You Send
1.You send a message (chat, webhook, or 💡 Smart Task chip) 2.AUTO ROUTE: scores all active nodes by keyword → picks winner (Jarvis = default) 3.SCAN: reads nodes, jobs, rules, preferred sites from this page 4.BLUEPRINT: Gemini builds the workflow using your rules as constraints 5.Workflow saved to /staff-temp automatically 6.REACT LOOP: Agent executes each step — Playwright browses, extracts, clicks 7.High-risk steps → Telegram approval request with Approve/Skip buttons 8.Result sent to Telegram + shown in chat. Visit /staff-temp to assign it to a staff member
💡 What This Page Controls
📋 Rules — constraints the AI must follow when building every workflow (e.g. always send to Telegram, never use more than 10 steps)
🌐 Preferred Sites — which websites to use for common task types (stock prices, flights, news, etc.)
✨ AI Instructions — a free-text system message injected into every blueprint build call
📦 Examples — reference workflows the AI uses to understand how you want things done
⚙ A-to-E State Machine — Full Workflow
Every prompt (webhook · Telegram · chat) runs through this pipeline. 0.3 is the master orchestrator — browser tasks are delegated to 0.8 which runs its own full A→E pipeline locally. Gemini 2.5 Flash · 5 keys · LiteLLM proxy :4000
🅐 STEP A1 — INTAKE
A-1 Receive the prompt from 0.3 (or direct webhook · Telegram) via POST /webhooks/agent · /run · /api/chat.
→ 0.3 sends the raw task prompt (~400 words) so 0.8 runs its own full pipeline independently
A-2 Gemini Flash classifies intent: existing_job · simple_question · complex_task · unclear.
→ If unclear (<3 words) — ask What / Where / Who before continuing
A-3 If simple factual question — search + Gemini synthesis → reply directly. Skip to E1.
→ DuckDuckGo top-5 snippets + Gemini summary. No blueprint needed.
🅑 STEPS B2–B7 — CONTEXT & BLUEPRINT
B-2 NocoDB pull — ALL_STAFF · all_jobs · tools · CLI · accounts · Composio · masterclass · job_workflows · rules_preferences.
→ rules_preferences auto-matches trigger keywords → preferred site URLs (e.g. "eurostar" → eurostar.com)
B-3 Web search — get relevant links and snippets for the task (DuckDuckGo · top 5 results · titles + URLs).
→ Parallel with B-4, 7s timeout each
B-4 How-to search — "how to [task] step by step best practices" · extracts page content from top 2 results.
→ Up to 700 chars per page for procedural context
B-5 Modular Transfer — review 3★+ past job_workflows from NocoDB. Reuse proven steps.
→ Top 6 rated workflows injected into blueprint prompt
B-6 Bundle context >600 words — TASK + STAFF + TOOLS + RULES + PREF_SITES + SEARCH + HOW-TO.
→ If under 600 words, fetch extra content from top search result
B-7 Blueprint Generation — Gemini creates 10 steps. Format: steptype|Label|action.
→ 12s timeout. If LLM fails/429 — pref_rules auto-builds steps from matched site rules instantly
🅒 STEP C — REPLY & EDIT WINDOW
C-1 Reply with workflow name + all steps with icons + delegation status (which VM will run it).
→ Link to /staff-temp?id=wf_id so steps can be edited before execution
C-2 30-second auto-run countdown. Reply run now to start immediately or edit any step first.
→ High-risk steps pause for Telegram YES/NO before executing
🅓 STEPS D1–D2 — BROWSER EXECUTION (local on 0.8)
D-1 Playwright Firefox runs locally on this machine (DISPLAY=:99 Xvfb). Screenshot per step → logs/screenshots/.
→ Cookie consent auto-dismissed · navigator.webdriver spoofed · Firefox fingerprint randomised
D-2 Cloudflare detection on every navigation. Auto-escalate: Firefox (Tier 1) → Chrome Incognito Stealth (Tier 2) → Human alert (Tier 3).
→ Detects "Just a moment" / "Ray ID" / Turnstile. Tier 3 fires Telegram VNC link for manual login
🅔 STEP E1 — OUTPUT & RESULT
E-1 POST result + screenshot back to 0.3 /api/worker-result · Telegram notification · MITOS overlay · 20-word TTS summary.
→ Screenshot viewable at 0.3:8080/screenshots/ · result stored for polling · training data written to demo_training.jsonl
⚡ Load & Reliability
Max 20 concurrent executions (semaphore). B-3/B-4 searches run in parallel (7s timeout each). LLM 12s blueprint timeout — instant pref_rules fallback if all Gemini keys 429. 0.3 sends raw prompt to 0.8:8080/webhooks/agent → 0.8 runs full A→E independently. Fallback: 0.8:8081/run-job (worker_listener direct Playwright).
🧠 Auto-Routing Logic
Before a workflow runs, the system picks which node handles it:
For each auto_eligible node:
  +5 if message matches a training trigger (exact phrase)
  +3 if message contains a category keyword
  +2 if message contains a specialty keyword
  +1 for each description word match

Highest score wins. Jarvis = default (wins on tie / zero scores)
